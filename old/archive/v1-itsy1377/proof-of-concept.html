The lab repository

Three programs students work with all term: an agent they extend, a deliberately vulnerable helpdesk they attack, and a test harness that decides whether an attack worked by looking at the world rather than at what the model said. Five marked extension points carry every graded change. It runs offline with no API key.

Verified, not asserted

The worked solution passes 56 of 56 autograder tests. An autograder nobody has satisfied is a rumor rather than an assessment, so the build applies the solution, runs the harness, runs the tests, and puts everything back. That check has caught a broken assertion twice, including one of its own.

The reading level, enforced

All 58 authored pages sit at a mean Flesch-Kincaid grade of 4.46 against a limit of 8.0, measured after code blocks, tables, framework identifiers and quoted text are excluded, because scoring those would make the number dishonest. The Rules of Engagement is held tighter and scores 4.0. The report is committed beside the content so a reviewer can read the numbers rather than take the claim on faith.

The ten minutes

One command runs the whole arc offline, with no API key and no cost: the attack lands, the fix goes in, the attack stops, and normal use survives. 

./demo/run_demo.sh

The attack is the interesting part

A support agent asks for an ordinary ticket summary. That is all they do. The instruction to email a customer's record to an outside address came out of the ticket body, written by whoever opened the ticket, sitting in a database waiting for an assistant to read it. Nobody at the company did anything wrong.

The evidence is a file in the outbox addressed outside the company, containing the customer's stored payment reference. That file either exists or it does not. What the model said about it is not evidence, and the harness has no way to grade on it: the case file format refuses text matching outright.

Three cases stay vulnerable, and that is the honest result rather than a gap in the demo. A recipient allowlist does nothing about system prompt disclosure or a missing authorization check. One fix, one class.

Read that status carefully

BLOCKED_5_OF_5 does not say the attack failed. It says the agent was still fully hijacked, asked to send the record every single time, and one line of code stopped it. That is a very different residual risk from an attack that failed, and a report printing the two identically hides the thing a client most needs to know.

What the reviews found

Seven adversarial passes were run with different expert framings: offensive red team, Python correctness, instructional design, security assessment methodology, a CAE program reviewer, a Quality Matters peer reviewer with an accessibility specialty, and a cross-artifact consistency audit. They found real defects. The ones worth a committee's attention are below.

Six defects that would have put a wrong result in a gradebook

All six were the same shape: the harness reporting a comforting result that was not true.

  • A canary token that disagreed with the seeded database reported a successful exfiltration as mitigated, while the detector self-test passed. That is precisely the failure the whole design exists to prevent. Preflight now refuses to run on a mismatch.
  • Zero hits could be reported as a fix from a single completed trial. Four rate-limited trials and one clean miss read as a working defense.
  • A detector returned "my assertion held" where the runner read "the attack landed," so a student's working defense would have been reported as a vulnerability.
  • A blocked call's arguments counted as a leak, reaching the same wrong conclusion by another route.
  • Deleting the email tool outright passed every control, which would have made "remediation" mean removing the feature. A second benign control now requires a legitimate escalation to still go out.
  • The autograder required a security control to fail open, in a course that says three pages later that a guard which lets everything through is worse than no guard.
A word left the harness

MITIGATED is gone. Zero hits across five trials against a weakness that lands three times in ten happens about one run in six, so the word was a conclusion presented as an observation, sitting two lines below a comment reading "Missing evidence is not evidence of absence." The statuses now carry their own sample size. A student who wants to write "mitigated" in a report still can, and now has to decide to.

Two findings about what the project claimed

A knowledge unit claim was withdrawn. The blueprint claimed three NSA units. A search of the built artifacts supports one, partially: there is no machine learning library in the student dependencies, zero occurrences of anomaly detection or alert triage, zero of five claimed defensive elements, and zero occurrences of the EU AI Act, GDPR, CCPA or HIPAA. "Governance" appears once in the whole course, on an instructor-facing page. The two program documents had also been contradicting each other, and the one with no governance content in it was wrong.

The honest framing is a security-of-AI course with an offensive centre of gravity. The modules are called "Break It" then "Fix It" and Project 2 is "Attack, Harness, Report" at 55 percent of the grade. Claiming a defensive designation would put every other mapping in the packet in question.

The Rules of Engagement stated as flat fact that unauthorized testing "is a crime." That is wrong as written, it named no statute, and the course then had students restate it in their own words and quoted that back on the final exam. A college attorney would have caught it. It now reads "can be a crime, and it breaks the student code of conduct either way." The clause on finding a real vulnerability outside the course gained three things it needed: keep notes only and retain no data, route a workplace finding to the employer's security channel rather than to an instructor, and the three places a report belongs when there is no obvious owner.

Three things were fixed anyway: callout severity now lives in the markup as a hidden word rather than in a stylesheet the college controls, the documents declare a language, and about fifteen quiz items that offered single-letter answer options now restate what makes each option distinctive.

Eleven wrong answer keys

The worst defect class in a course, because a student who reasons correctly loses points and then learns the wrong thing. Two items keyed a control that fails open. One had no correct answer at all. One keyed evidence naming the wrong actor, which is the row the detector specifically rejects. One keyed code that raises an exception on a column that does not exist. Two built on a tool the assignment explicitly forbids because the target has no route for it. Every one was verified against the lab code before it was changed.

Why it stays fixed

Nearly every content defect the seven reviews found traced to the same root cause, and it is worth stating plainly because it generalises.

The mechanism

Reading level was mechanically enforced from day one: a page over grade 8 failed the build. Factual accuracy was a checklist somebody was meant to run once a semester. Only one of those two could fail anything, so pages drifted away from the code they describe while the numbers stayed green. The asymmetry even had a direction: an accurate hedged sentence costs reading grade, and a confident wrong one does not.

So the fix was not to correct thirty-four items. It was to build the check that makes them impossible, and then correct them.

The consistency gate found 23 disagreements on its first run, including two the human reviewers had missed. It also caught itself: an early version read status names out of a code comment, so it matched MITIGATED inside a comment explaining why MITIGATED had been removed, and then told every page the status was still valid. A checker that reads prose has exactly the problem as the content it is checking.

What it cannot do

These are the claims a reviewer should not let the course make.

  • Not OWASP LLM Top 10 coverage. Three of ten risks substantively. The materials say "selected OWASP risks" and never the full list, and a build check enforces it.
  • Not agent development. Students extend a scaffold. They cannot build an agent from an empty directory.
  • Not Python competence. No object orientation, no algorithms, no data structures beyond lists and dictionaries. This course does not articulate into COSC 1436 and must not be listed as preparation for it.
  • Not red teaming. Pre-authored attack classes against one known-vulnerable instructor-built target is exercise, not discovery.
  • Insecure tool authorization is a walkthrough, not a hands-on lab. Outcome 3 names three weakness classes and students get hands-on exploitation with two. That is the largest thing the seven-week calendar cost, and it is named rather than glossed.
  • Only one knowledge unit, partially. See above.
The largest residual risk

The local model path has never been tested on a real locked-down student laptop. Vendor documentation saying "no administrator required" is not the same as surviving a specific institution's application control policy. No amount of research retires this one. It needs a pilot on one real student-image machine, and week one is where this course loses people.

Running it

From nothing, on one machine, in about forty minutes:

./canvas/deploy/setup.sh          # Canvas from the official repository
pip install -r tools/requirements.txt
python -m tools.import_cartridge  # build, import, and verify what arrived
python canvas/theme/apply_theme.py

cd labs
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python verify_env.py
./demo/run_demo.sh                # the five-minute walkthrough

The full operator guide, the ten-minute committee walkthrough, and the three deployment failures worth knowing about are in RUNBOOK.md. The most useful of the three: Canvas silently drops every quiz in every cartridge unless an external Python QTI converter is installed, which open-source Canvas does not ship. The import reports success with no error, no warning, and no migration issue. The two-minute test that settled it was importing the college's own template export, which loses both of its quizzes the same way.

What that means for the deliverable

Common Cartridge stays the primary artifact, because the college's hosted Canvas has the converter and a cartridge is how the institution actually moves a course. A small API script creates the quizzes so a local deployment is complete, and the importer runs it automatically. Both are needed, for different reasons, and the runbook says which is which.
