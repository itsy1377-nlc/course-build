::: learned | What You Learned
1. A model picks among several words that would fit, so two runs can differ.
2. In an agent that matters more, because one of those picks is which tool to call.
3. You compare runs on features you can count, not on how the replies read.
4. A part that held across five runs is a result, and so is a part that varied.
5. One run proves nothing, which is why this course runs five trials.
:::

::: did | What You Did
1. Sent one request five times and kept a trace for every run.
2. Sent five ordinary requests of your own, once each.
3. Built comparison tables with one row per run.
4. Read the supplied counting script, changed one line, and ran it on your folder.
5. Wrote what varied, what held, and what ten runs do not settle.
:::

::: checkpoint | Check Yourself
1. Your five runs called different tools in different orders. Is your lab broken?
2. Which is stronger evidence that two runs differed: the final replies, or the
   tool calls?
3. A tool appeared in 1 of your 5 runs. Is that worth reporting?
4. Write a correct sentence about a tool that appeared in all five runs.
5. Somebody asks you to prove the agent never sends mail. What can you honestly
   say?
6. One run stopped before it reached the model. Does it go in your table as a run
   with no tool calls?

Answers:

1. No. Variation between runs is how these systems behave. It is the finding, not
   a fault to report.
2. The tool calls. Two runs can read almost the same and have done different
   things.
3. Yes. Once in five is a real event. The count is how you report it, and later
   weeks treat a single hit as worth chasing.
4. Answers vary: "in five trials, the agent called the lookup tool in 5 of 5
   runs."
5. That in five trials you did not observe a send. Five clean runs are not never,
   and the honest sentence says how many trials it rests on.
6. No. That is a broken run, not a trial. Note it, say why it broke, and run
   another one in its place.
:::
