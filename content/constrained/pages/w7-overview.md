::: intro
This week your control meets attacks other students wrote. You run it against
the class pool, change one thing, and run again. Then you point the finished
control at your own week 3 case.
:::

::: objectives
By the end of this week you will be able to:

1. Run your control against attack cases you did not write, and record what each run returned.
2. Revise a control once, using a failure you can name.
3. State what your control reaches, and what sits outside it.
:::

::: scope | Authorization and Scope
The pooled cases are files, and you run them yourself. Your permitted targets
have not changed:

1. The practice target this course gives you.
2. The agent you build.
3. A language model running on your own computer.

Never a commercial AI service. Never a classmate's computer. Read the Rules of
Engagement page in Start Here again before the session. If a pooled case asks
for anything outside those three targets, stop and tell your instructor.
:::

| Part | Hours |
|---|---|
| Reading | 1.0 |

| The live session, both rounds | 2.0 |
| The revision between rounds | 1.0 |

| **Total** | **6.5 to 7.0** |

Students new to programming often take two to three times as long on the code
change. That puts a realistic week between about 10 and 20 hours. The evidence
file is due this week too, and it carries its own estimate on its own page.
Plan for both.
:::

::: next | What's Next
The evidence file closes the course. Your standing on the board, the change you
made between rounds, and this week's last result all belong in it. Write each
one down as you go. The board keeps the numbers; it does not keep your reasons,
and the reasons are what the report is graded on.
:::
