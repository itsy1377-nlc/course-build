::: intro
This week you stop being a reader of the harness and start being an author of
it. You add cases of your own, you learn what its numbers actually claim, and
you fix one weakness in code and prove the fix held.
:::

::: objectives
By the end of this week, you will be able to:

- 7.1. Add an attack case to the harness as a YAML file the schema accepts.
- 7.2. Explain why an attack and a fix are judged by different thresholds.
- 7.3. Sort a result into pass, fail, or inconclusive, and say why an errored
  trial is never a failed one.
- 7.4. Implement one fix in code and verify it against two suites.

These serve course outcomes O4 (running the harness and reading its results),
O5 (documenting findings and fixing inside a scope), and O3 (finding
weaknesses in agents).
:::

::: scope
Everything this week runs against HelpDesk Lite on your own computer. Nothing
else. The Rules of Engagement apply to the cases you write yourself, exactly
as they apply to the shipped ones.

Every case file carries a line that says `authorized: true`. That line is not
paperwork. It is where scope lives in a file a grader can read.
:::

::: callout time | About how long this takes
Reading and the content page: about 90 minutes.
The Reading Results exercise: about 30 minutes.
Writing two cases: about 1 hour.
The fix, plus running the harness before and after: about 3 hours.
Writing it up: about 1 hour.
The quiz: about 30 minutes.

That is about 7.5 hours of assigned work in total.

If programming is new to you, the coding parts commonly take two to three
times as long. That wider range is normal, not a sign of falling behind.

The fix is the part that runs long. Budget an evening for it, not an hour.
Start on Wednesday if you can.
